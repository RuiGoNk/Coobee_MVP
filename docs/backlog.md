# CooBee — Бэклог (после MVP)

> Фиксирует фичи, которые НЕ входят в MVP (недели 1–4), но архитектурно
> заложены заглушками. Реализация — спринт 5+.

## Важно: денег не собираем

Сервис **не принимает платежи** и **не собирает деньги** на подарки.
Только: подбор → голосование → ссылка на покупку (маркетплейс/сертификат).
Никаких эскроу, сбора средств, чеков, возвратов.

---

## Фича 1: Тайный Санта

**Суть.** Группа участников (например, коллектив, семья, друзья) проводит
жеребьёвку: каждый получает «кому дарит» (без взаимности), бюджет задаётся
группой. Подарок подбирается под **анкету получателя** (он её заполнил при
регистрации) и бюджет — не «пальцем в небо».

**Ключевое:** анкета участника = его же профиль получателя. Переиспользуем
`user_profiles`. Новых анкет не вводим.

**Модель (спринт 5):**
- `groups` (id, owner_id, name, kind='santa', budget_range, created_at)
- `group_members` (group_id, user_id, role)
- `group_invites` (token, group_id, expires_at, used_by)
- `santa_assignments` (group_id, giver_id, receiver_id, drawn_at)

**API (заглушки сейчас):**
- `POST /groups` — создать группу (kind=santa)
- `POST /groups/{id}/invite` — ссылка-приглашение
- `POST /groups/{id}/join` — вступить по токену
- `POST /groups/{id}/santa/draw` — жеребьёвка (без взаимности)
- `GET /groups/{id}/santa/my-receiver` — кому дарю + подборка

**Переиспользуем:** `recommend` (профиль получателя + бюджет), `feedback`.

## Фича 2: Групповой выбор подарка (комната)

**Суть.** Группа (например, родители на Новый год для 30 детей) создаёт
«комнату»: задаёт бюджет на одного получателя / количество. Сервис подбирает
варианты, участники **голосуют**, выбирается победитель, все получают ссылку
«купить N штук». **Без сбора денег** — каждый покупает сам.

**Модель (спринт 5):**
- `rooms` (id, owner_id, name, budget_per_item, quantity, occasion, status)
- `room_members` (room_id, user_id)
- `room_candidates` (room_id, catalog_id, added_by)
- `room_votes` (room_id, candidate_id, user_id) — уникально (room, candidate, user)
- `room_winner` (room_id, candidate_id, decided_at)

**API (заглушки сейчас):**
- `POST /rooms` — создать комнату
- `GET /rooms/{id}` — состояние (кандидаты, голоса, победитель)
- `POST /rooms/{id}/candidates` — добавить кандидата (или сгенерировать подборкой)
- `POST /rooms/{id}/vote` — голос
- `POST /rooms/{id}/close` — выбрать победителя

**Переиспользуем:** `catalog`, `recommend` (генерация кандидатов по бюджету).

## Точки интеграции в MVP-код

- `POST /recommend` — сейчас принимает `recipient_id`. Для Санты нужен режим
  «по профилю без получателя»: заложить опциональный `profile_override` +
  `budget_override` (сейчас — `TODO`, игнорируется).
- `feedback` — переиспользуется для лайков в Санте/комнатах (контексты
  добавим: `santa`, `room`).
- `user_profiles` — источник анкеты для Санты (участник = получатель).

---

## Что НЕ делаем (явно)

- Платежи, сбор денег, эскроу, чеки, возвраты.
- Чат внутри групп (на MVP не нужен).
- Push-уведомления (только Telegram-бот, если привязан).
